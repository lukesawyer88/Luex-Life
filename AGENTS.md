# Luex Life – rules for anyone building here

Luex Life is the family and household app from Luex. It is a **separate app with its own repo and its own Supabase database** from Luex Work (the business app). Nothing here may depend on Work: borrow by copying code, never by linking.

- **Owner's rules (26 Oct 2026):**
  - The whole app fits on one screen on phones, tablets and desktop. The page itself never scrolls; only a window inside it may.
  - The "drunk grandma test": if a drunk grandma couldn't use a screen, make it simpler.
  - Plain-English, sentence-case copy. British spelling. Lists shown to the owner are numbered lists.
  - Same design as Luex Work (black sidebar, white frame, grey-blue records window, cream detail window). Colours live in `src/styles.css` only.
  - Make exactly the change asked, only where asked. Don't start the next job unprompted.
- **Stack:** Vite + React 19 + TypeScript (strict) + Tailwind v4 + shadcn/ui parts (`src/components/ui`) + TanStack Router and Query + Supabase. A plain single-page app: Cloudflare Pages serves `dist/`. Server jobs live only in Supabase Edge Functions (`supabase/functions`: push-sender, import-feeds) run by pg_cron. The store apps (App Store, Google Play) will wrap this same app with Capacitor near launch.
- **Code goes through GitHub.** Merge to `main` yourself; Cloudflare builds from it. Never rewrite pushed history.
- **Supabase project:** `luex-life`, ref `pjttemdnnnnlfijvoeip` (eu-west-1). Never touch the "Luex App" (Work) project.
- **No live database changes without the owner's yes.** Every change is a migration file in `supabase/migrations` (and applied to the live project only when approved).
- **Access is enforced in the database, not only by hiding buttons.** Row-level security on every table. New tables and functions get no access by default: every migration revokes everything and grants exactly what's needed, with one policy per command. Functions are `security definer` with `set search_path = ''` and check who is calling.
- **After ANY change to access, run both test files** (`supabase/tests/access_test.sql` and `supabase/tests/app_calls_test.sql`) against the live project with the SQL tool. Each ends with an error that carries the report and rolls itself back; all passed = "REPORT: ALL n CHECKS PASSED". Add checks for everything new.
- **Roles:** `parent` (admin; sees bills and papers), `member` (adult relative or babysitter), `child`. A person can be a profile without a login (managed by a parent). Logins join only through invites. A family always keeps one parent who can log in.
- **Modules:** the 15 agreed modules live in `src/modules/registry.ts`. Adding or building a module changes the registry entry and adds its own page and tables; it never changes the shell. Which modules are parent-only is set there (`audience`) and must also be enforced in each module's tables when they are built.
- **Children's data:** keep it minimal. Pictures are private and compressed. Health is dates only, never records. Get an adviser's view before building Family Health and Kids' Space.
- **AI:** the only AI in Luex is the Luex assistant. Any other AI feature must be agreed with the owner first. No AI credits spent without asking.
- **Built:** Family Calendar (module 2) with web push notifications and calendar import; Family Board (module 3: chats, photos, lists, notes, goals, journal; album links through the `album-share` function). Food (module 4: meal plan, recipes with link import and on-phone page scanning, shopping lists that learn aisles, fridge and freezer, packed lunches, takeaways, parents' food budget, private calories for grown-ups; `recipe-import` function). Household Money (module 5: budget, payments with statement import, bills and subscriptions, savings and gift budgets, loans, investments, credit score, reports and export; parents only). Rewards and Pocket Money (module 6: habits and personal rewards for anyone, shared rewards and up-for-grabs jobs, children's pocket money, stars and reward shop). Test files: `supabase/tests/access_test.sql`, `app_calls_test.sql`, `calendar_test.sql`, `board_test.sql`, `food_test.sql`, `money_test.sql`, `rewards_test.sql`, `school_test.sql`, `documents_test.sql`, `emergency_test.sql`, `home_test.sql` (run all eleven after any access change; `school_test.sql` needs a time zone at 7–9am somewhere, so one check can fail at some hours). Module pages load only when opened (`src/pages/module.tsx`).
- **Board rules to keep:** a grown-up with a login can never be turned into a child; parents read a child's chats only from when the child joined, and never post in them; journal openness is stamped on each entry; every Board read policy starts with `family_id = my_family_id()` (speed and safety).
- **Food rules to keep:** calories are private to the person (not even parents) and grown-ups only; the food budget is parents only; children only request dinners; recipe import never stores files itself (the app saves the picture under the person's own rules).
- **Money rules to keep:** parents only, enforced in every policy through `money_ok`; "just mine" (`private_to`) is only ever yourself, only the creator can make a shared thing private, and privacy follows the account, bill or pot a row hangs off; nothing switches between private and shared once the other parent has added to it; Food shops are always shared; private payments never change a shared bill's amount; imported-line duplicates are checked per owner; one storage allowance covers Board, Food and Money files.
- **Rewards rules to keep:** Luex Life is for anyone (single adults, couples, flatmates, families); nothing depends on a bank or outside app. Stars and money come only from real events or a parent (for a child); every balance check locks the person first; nothing takes a balance below nothing; a child's pay for a job needs a parent; a person's things are seen by them and by parents only when the person is a child.
- **Simple first (27 Oct 2026):** Luex Life simplifies and organises home and family life. Extras beyond that are switched off by default and switched on by a parent in Settings → More features (`src/lib/extras.ts`, stored as `x:<key>` rows in `family_modules`). The list of what was trimmed is `docs/more-features.md`. New extras go in that file and behind `useExtra(key)`.
- **New modules go live in this order:** database first (with the owner's yes), then wire the page into `src/pages/module.tsx` and Home. Never put a page that needs new tables on `main` before its database is live (Cloudflare deploys `main`).
- **School rules to keep:** a view on top of the Calendar (clubs and babysitting are Calendar events, and only events everyone can see); only grown-ups do the school run; the morning summary tells parents about every child, a child about themselves and other grown-ups only about their own runs.
- **Documents rules to keep:** grown-ups only (audience "adults"); household papers are for parents, "just mine" papers for their owner only (not even parents); children see nothing; privacy is fixed when added; pages live in `doc-files` under `<family>/docs/s/` or `<family>/docs/p/<owner>/`; papers kept on a phone (Cache API `luex-docs`, `luex.docs.*` keys) are cleared on sign-out.
- **Contacts and Emergency rules to keep:** everyone (children too) reads it; grown-ups keep contacts and home essentials; each grown-up keeps their own card, parents the children's, pets' and profiles without a login; hidden conditions (`em_conditions.shared = false`) only for whoever keeps the card; babysitter links (`/e/<token>`, `em_shared`) show only children's and pets' cards, the call list and home essentials (Wi-Fi only when ticked) and never need sign-in; its queries (`"em"`) are kept on the phone so it works with no signal.
- **Home Care rules to keep:** cleaning stays in the Calendar's Chores (they pay stars and pocket money); Home Care is bins, yearly jobs, things to fix and meter readings; everyone reads; grown-ups set up; anyone (children too) adds something to fix and changes their own until it's fixed; a child is on a rota or owns a job only when a parent says so; the client's bin rota maths (`collections`, `binPerson` in `src/modules/home-care/data.ts`) must match `hc_bin_is_day` and `hc_bin_person`.
- **Links into a page:** read `?tab=`, `?doc=` and the like with `takeLinkParams()` (`src/lib/link-params.ts`), never `window.location.search` plus `replaceState` directly: a page can be set up twice while the app starts, and the second must still see the values.
- **Saved-offline data must be plain JSON:** queries kept on the device (`KEEP_OFFLINE` in `src/router.tsx`) return arrays or objects; turn them into Maps or Sets with `select`.
